# 기가트론의 작은 칩 수에서 Swiver가 가져올 수 있는 것

작성일: 2026-10-23. 현재 Swiver의 ISA, 비중첩 순차 실행, 공통 8비트 hi/lo 버스, 기존 12칩 74 ALU, 외부 바이트 저장, ATF1504×2와 ATF1502×1 조건을 유지하는 연구다. 직전 [연구노트](research-notes-2026-10-23.md)의 ROM-free FSM 논의를 구체화한다. 기존 CPU나 CUPL 생성기는 수정하지 않았다.

후속 구현: 조사 이후 [INC/DEC ALU 연결 후보](README.md)를 구현·실행했다.
이 문서의 수치와 “미구현” 표현은 조사 당시 ADD/SUB 전용 기준을 보존하며,
실제 개선 결과는 README와 [실행 근거](incdec-evidence.json)를 따른다. 새 CU fit은 아직 별도다.

## 1. 조사 결과

기가트론은 Swiver에도 도움이 된다. 특히 **부품이 이미 제공하는 기능을 활용하고, 제어를 동작 종류·소스·목적지로 나누는 방법**이 유용하다. 그러나 기가트론의 칩 수를 Swiver의 목표 수량으로 그대로 옮길 수는 없다. native ISA, 메모리 구조, 파이프라인, 소프트웨어가 맡는 역할이 다르다.

이번 조사에서 가장 직접적인 개선 지점을 찾았다. Swiver의 기존 12칩 ALU는 INC/DEC를 지원하지만, 현재 하이브리드 모델의 `Circuit.import_alu()`는 ADD/SUB 제어만 연결한다. 따라서 PC/RP를 1만큼 바꿀 때마다 `MBR ← 1` 전송을 먼저 수행한다. 이 전송이 네 시험 프로그램 전체 tick의 **12.7~14.3%**를 차지했다.

이 비율은 현재 모델에서 실제 측정한 낭비 후보의 크기다. 아직 전송을 제거한 CPU나 수정 CU의 fit을 만든 것은 아니므로 달성한 성능 개선이라고 읽지 않는다. 하지만 ALU를 CPLD로 옮기거나 추가 제어 ROM을 넣기 전에 손볼 구체적인 대상이다.

## 2. “36칩”의 집계 범위부터 맞추기

공식 [2020-03-20 회로도](https://cdn.hackaday.io/files/20781889094304/Schematics%202020-03-20.pdf)의 U1~U39를 확인했다. 74 계열은 36개이며, ROM 1개·RAM 1개·전원 감시/리셋 IC 1개까지 세면 39개다. CPU만의 논리 수와 주변 입출력을 포함한 보드 수는 다르다. 개발자의 [프로젝트 설명](https://hackaday.io/project/20781-gigatron-ttl-microcomputer)은 CPU proper를 34 TTL IC로 표현한다.

회로도에서 확인한 집계는 다음과 같다. 이 표는 패키지의 기능별 분류이며 배선·수동부품 수를 포함하지 않는다.

| 기능 | 74 패키지 | 회로도 참조 |
|---|---:|---|
| 클록 | 1 | U1 |
| 16비트 PC | 4 | U3~U6, 161 |
| IR·D와 D 버스 버퍼 | 3 | U8~U10 |
| CU | 6 | U11~U16, 139·153·138×2·240·32 |
| ALU | 10 | U17~U26, 153×8 + 283×2 |
| AC·AC 버퍼·X·Y·OUT | 6 | U27~U31, U37 |
| 메모리 주소 선택 | 4 | U32~U35, 157 |
| 확장 출력·입력 | 2 | U38~U39 |
| 합계 | **36** | 메모리와 전원 감시 IC 제외 |

CU에는 다이오드와 저항 네트워크도 들어간다. “CU 6칩”은 제어 배선이나 부품이 여섯 개뿐이라는 뜻이 아니다. Swiver 32 IC 후보에는 메모리와 CPLD가 포함되고 외부 코프로세서는 빠져 있으므로, 숫자만 나란히 두어 우열을 판단하면 안 된다.

## 3. 작은 CU를 가능하게 한 구조

공식 [native 동작 모델](https://raw.githubusercontent.com/kervinck/gigatron-rom/master/Docs/gtemu.c)과 회로도 3~7쪽을 대조했다.

- 명령 필드는 연산 3비트, 주소/조건 3비트, 버스 소스 2비트로 분리된다. 디코더가 각 필드의 역할을 직접 펼친다.
- 프로그램은 16비트 폭 ROM에서 IR과 D로 함께 들어온다. 데이터 RAM은 별도다. 인출과 이전 명령 실행이 겹치는 구조다.
- PC는 전용 161 네 개로 증가한다. X도 161 두 개로 저장과 증가를 겸한다.
- AC·Y·OUT은 enable이 있는 377을 사용한다. AC만 데이터 버스로 되돌려 보내고 다른 레지스터는 용도별 경로로 소비한다.
- 조건 분기는 AC와 ALU 조건을 사용한다. 복잡한 stack CALL/RET나 Swiver의 검사 계약을 같은 native 하드웨어로 구현한 비교 대상은 아니다.

RAM의 프로그램과 복잡한 응용 동작을 제공하는 소프트웨어 계층도 중요하다. 개발자는 vCPU 인터프리터와 소프트웨어 기반 주변 기능을 명시한다. [공식 소프트웨어 저장소](https://github.com/kervinck/gigatron-rom)의 kernel·vCPU와 [개발자 설명](https://hackaday.io/project/20781-gigatron-ttl-microcomputer)을 근거로 한다. native 처리량과 인터프리터 처리량은 구분해야 한다.

이것은 “정교하게 설계하면 같은 기능을 아무 비용 없이 줄일 수 있다”는 사례가 아니다. 하드웨어가 쉽게 수행할 수 있는 연산을 native 명령으로 정하고, 나머지를 소프트웨어와 사용 규칙에 맡긴 사례다.

## 4. 현재 조건 안에서 적용할 수 있는 방법

### 4.1 ISA는 유지하고 내부 제어만 규칙적으로 나누기

기가트론의 외부 opcode를 복사할 필요는 없다. Swiver opcode를 내부 명령 class로 분류한 후 `class + 실행 단계 + byte 선택 + 공통 절차 복귀 위치`로 제어할 수 있다. 이 방식은 앞서 논의한 PC/RP 증감·피연산자 인출·CALL/RET 공통 절차 공유와 연결된다.

현재 `Graph.add()`의 키는 `(transfer, successor)`이므로 같은 동작도 후속 상태가 다르면 복제된다. 292개 상태 중 서로 다른 전송/정지 표식은 43종이다. 공통 절차를 도입하면 중복 상태 디코드와 다음 상태 식을 줄일 가능성이 있다. 기가트론이 그 압축 결과를 증명하는 것은 아니며, 변경한 CUPL의 product term·MC·핀을 실제 fitter로 확인해야 한다.

### 4.2 기존 ALU의 INC/DEC 활용: 이번에 확인한 우선 대상

[ALU 사양](../../../reference/hardware/alu-opcodes-timing.md)과 현재 [ALU preset](../blocks/alu8.py), [import_alu](../ttl/netlist.py)를 대조했다.

현재 증가 절차는 대체로 다음 세 전송이다.

```text
MBR ← 1
RESULT ← ALU(PC_LO + MBR)
PC_LO ← RESULT
```

carry가 발생하면 상위 바이트도 같은 세 전송을 수행한다. RP의 ±1 및 상위 바이트 carry/borrow 처리에도 비슷한 경로가 있다. 기존 ALU의 INC/DEC는 외부 B 값에 의존하지 않으므로, 제어를 노출하면 `MBR ← 1`을 생략하는 두 전송 후보를 만들 수 있다. RP의 −2를 자동으로 한 번의 DEC로 바꿀 수는 없다.

이 개선은 **ALU 12칩을 유지**하며, RESULT 래치도 그대로 둔다. 공유 DBUS에서 결과를 바로 되먹임할 때의 hold 문제를 이번에 해결했다고 가정하지 않는다.

추가 제어에는 비용이 있다. 현재 ADD/SUB 연결은 SUB와 반전 신호에 bctrl과 carry-in을 묶어 둔다. ADD/SUB/INC/DEC를 모두 선택하려면 bctrl 하위 쌍·상위 쌍·carry-in을 독립적으로 지정할 수 있어야 한다. 현재 성공한 AUX는 일반 I/O 28/28을 사용한다. 따라서 기존 핀 배치를 그대로 두고 기능만 켜는 수정은 아니며, 다른 CPLD로 출력을 옮기거나 기능 인코딩을 재배치해야 한다. MC와 핀의 비용까지 포함해 다시 fit해야 한다.

### 4.3 377·161 같은 부품 기능을 적재적소에 사용하기

all-74 비교 모델은 저장 유지에 574+외부 feedback MUX를 사용한다. 출력이 항상 필요한 레지스터라면 enable 내장 부품으로 유지 MUX를 줄이는 방향을 검토할 수 있다. 이는 185/167개 all-74 후보에서 특히 의미가 있다.

현재 하이브리드 bank는 574의 tri-state 출력을 공통 DBUS에 연결하고 개별 클록을 제어한다. 기가트론의 377은 동일한 교체품이 아니다. 버스 출력 격리를 별도로 마련해야 하므로 574를 일괄 377로 바꾸면 감소를 보장하지 않는다. 항상 출력되는 주소/MBR와 DBUS를 구동하는 bank/TMP/RESULT를 구분해야 한다.

### 4.4 PC 전용 카운터는 두 번째 비교 후보

기가트론의 PC 전용 증가 경로는 CU가 매번 바이트 연산을 지시할 필요를 줄인다. Swiver에서도 ISA와 비중첩 실행을 유지하면서 전용 PC 카운터를 쓸 수는 있다. 다만 공통 8비트 버스로 PC low/high를 읽고 쓰는 경로까지 계산해야 한다.

예를 들어 161 네 개는 16비트 저장·증가를 제공하지만 tri-state 출력은 제공하지 않는다. PC 두 바이트를 DBUS로 선택 출력하기 위해 octal 버퍼 두 개를 쓰는 단순한 배치는 **카운터 4 + 버퍼 2 = 6개**로, 기존 PC용 574 두 개보다 4개 많다. 이는 한 블록의 예시 산술이며 완성 후보 BOM이 아니다. hi/lo 개별 load, carry, WAIT, reset 연결도 필요하다.

따라서 전용 카운터가 총 칩 수를 줄이려면 CU가 단순해져 다른 칩이나 ROM을 없애는 이득이 그 비용보다 커야 한다. 빠른 PC를 얻는 선택과 적은 패키지를 얻는 선택은 같지 않다. 우선 기존 ALU INC/DEC와 공통 절차를 시험한 다음 비교하는 순서가 합리적이다.

## 5. 현재 조건에서는 그대로 가져오지 않을 것

- **Harvard + 16비트 명령 ROM + 인출/실행 겹침:** Swiver의 통합 메모리·RAM native 실행·비중첩 조건을 바꾼다. CU를 단순하게 만드는 큰 요인이지만 직접 이식하지 않는다.
- **CALL/RET와 스택 처리를 소프트웨어로 이동:** 지금 ISA가 제공하는 접근 순서와 오류 처리를 바꾼다. vCPU의 기능과 하드웨어 native 기능을 섞어서 칩 수를 비교하지 않는다.
- **플래그 저장 생략:** Swiver BEQ는 이전 연산의 Z를 사용하므로 기가트론의 현재 AC 조건 검사를 그대로 적용할 수 없다.
- **기가트론 10칩 ALU로 교체:** 구조 비교 자료로만 사용한다. 기존 12칩 ALU 유지 조건과 별개인 변경이다.
- **다이오드 제어 행렬로 CPLD 대체:** 패키지 수는 작게 보일 수 있어도 저항·다이오드·교차 배선이 늘 수 있다. 배선 단순화라는 현재 목적에 자동으로 유리하지 않다.

## 6. 로컬에서 실제로 재본 비용

새 [gigatron_probe.py](gigatron_probe.py)는 기존 HybridCpu의 `_adjust()`를 관측하여 PC/RP 증감과 상수 적재만 센다. 연산·전송 동작은 바꾸지 않는다. 네 프로그램에서 각 명령 완료 상태, 메모리 전체 내용, 모든 메모리 접근 주소·값·순서를 기준 CPU와 비교했다. WAIT 없는 바이트 버스 모델이며 제어 ROM 읽기는 포함하지 않는다.

| 프로그램 | 전체 tick | PC 증가 내 전송 수 | PC/RP의 `MBR ← 1` 횟수 | 해당 적재 tick | 전체 비중 |
|---|---:|---:|---:|---:|---:|
| 반복 Fibonacci | 10,292 | 1,029 | 343 | 1,372 | 13.33% |
| 재귀 Fibonacci(3) | 7,568 | 663 | 241 | 964 | 12.74% |
| 재귀 Fibonacci(8) | 114,160 | 10,155 | 3,653 | 14,612 | 12.80% |
| ADD 256회 | 14,372 | 1,542 | 514 | 2,056 | 14.31% |

첫 번째 프로그램에서는 PC 증가 자체가 1,029/2,573 = 약 40.0%의 전송을 차지한다. ALU를 공유해 패키지를 아끼는 대신 얼마나 많은 제어 전송을 쓰는지 보여 준다. 상수 적재 제거만의 13.33%와 PC 증가 전체 40.0%를 혼동하지 않는다.

현재 그래프에는 `MBR ← 1` 상태가 65개 있다. 이를 단순히 292−65 = 227개 또는 65 MC 절감으로 보고하지 않는다. 공통 suffix, 복귀 정보, 명령 인코딩, 추가 ALU 제어 식을 바꾸면 최종 상태·논리 수가 함께 달라진다.

기존 실제 부품 ALU의 exhaustive 검증도 이번에 실행했다. INC와 DEC 각각 A/B의 65,536개 조합, 총 131,072개 조합을 다루는 두 pytest 사례가 통과했다. 이는 기존 ALU의 기능 근거이며 새 CU 연결이나 fit의 근거는 아니다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m simulators.cyclesim.hybrid.gigatron_probe
.\.venv\Scripts\python.exe -X utf8 -m pytest -q simulators/cyclesim/tests/test_alu12.py -k 'all_65536_pairs_per_preset_actual_chips and (INC or DEC)'
```

관측 JSON은 `simulators\cyclesim\build\hybrid\gigatron-profile.json`에 재생성된다. 소스 해시와 조건을 포함한다. 기록 사본은 [gigatron-profile-evidence.json](gigatron-profile-evidence.json)이다.

## 7. 후속 설계에 주는 결론

우선 검토할 조합은 **외부 74 ALU의 기존 INC/DEC 제어 활용 + 공통 절차형 FSM + 명령 class/단계별 디코드**다. ISA나 프로그램 메모리 구조를 바꾸지 않고 현재 불필요한 전송과 중복 제어를 함께 줄이는 방향이다. 기가트론의 작은 CU는 규칙적인 제어 분해가 유효한 설계 접근임을 보여 주며, 실제 Swiver 측정은 그 접근을 적용할 구체적인 비용을 드러낸다.

이번에 확정한 것은 적용 가능한 기법과 측정된 비용이다. 최종 ROM-free 칩 수, MC 사용량, 핀 수용, 속도 향상은 아직 확정하지 않았다. 총 칩 수 감소는 이러한 재구성으로 제어 ROM 또는 제어용 외부 칩을 실제 제거하고, 필요한 새 제어·버퍼까지 합친 뒤 판정한다.

자료 선택에는 Jev `jev-1.14.0`을 사용했다. 로컬 후보 5개를 Noul로 평가했고 입력 16,464/output 89 tokens, 캐시 재사용 0이었다. 현재 코드처럼 명시적으로 필요한 원본은 낮은 관련성 점수와 무관하게 직접 확인했다. 이 기록은 비용 공개이며 절감률이나 설계 타당성의 증거가 아니다.
