# 830 빵판 배치 탐색기

로컬 뷰어의 **830 배치 탐색** 탭에서 사용한다. 현재 ALU의 74HC153 8개,
74HC283 2개, 74HC157 2개를 대상으로 하며 CPU·ALU의 전기적 계산은 바꾸지 않는다.

```powershell
uv run --python .venv\Scripts\python.exe -m simulators.cyclesim viewer --reload
```

## 사용 순서

1. 빵판 수(2–8장), 배열, 간격, 지그재그 오프셋을 정한다.
2. **8–2–2 단계 유지**, **4비트씩 두 묶음**, **자유 배치** 중 묶음 조건을 고른다.
3. 배선 길이·가독성·절충 중 우선순위를 정하고 탐색한다.
4. 후보를 선택하고 넷별 경로를 확인한다. 기본은 캐리 연결이다.
5. 칩을 클릭하거나 **칩 찾기**에서 선택한다. 보드·시작 행·홈 방향을 바꾸고
   고정할 수 있다. **선택 칩 확대**는 핀 주변 구멍을 자세히 보여 준다.
6. 보드 좌표 직접 편집에서 각 보드의 X/Y/회전을 바꿀 수 있다.
   적용 후 배열이 **직접 지정**으로 바뀌며 그 배열에서 칩 배치를 다시 탐색한다.
7. 배치 JSON을 저장하고 다시 불러오거나, 신호 점퍼 CSV를 내려받는다.

고정은 **해당 보드 번호 안의 칩 행·방향**을 유지한다. 보드 자체의 월드 좌표는
배열 선택에 따라 바뀐다. 보드 위치까지 유지하려면 직접 지정 배열을 사용한다.
묶음 순서는 보드 번호 → 시작 행 기준이다. 임의의 보드 회전·배열에서 화면의
왼쪽→오른쪽 방향과 항상 같지는 않다.

잘못된 행·보드 중첩·칩 중첩·고정 조건 위반은 적용하지 않고 이전 결과를 유지한다.
설정을 바꾸면 기존 그림은 이전 결과임을 표시하며, 늦게 온 응답은 새 설정을 덮지 않는다.
저장 파일을 불러올 때 배치와 경로를 Python에서 재검증한다.

## 범용 보드 모델

`generic-830-v1`은 특정 구매 제품의 실측값이 아닌 공통 작업용 가정이다.

| 항목 | 모델 |
|---|---|
| 외곽 | 55 × 165 mm, 결합 돌기 제외 |
| 중앙 접점 | 63행 × 10열 = 630개 |
| 전원 접점 | 50개 × 4줄 = 200개 |
| 행 피치 | 2.54 mm |
| 접점 연결 | 같은 행 a–e / f–j 각각 연결, 중앙 홈에서 분리 |
| DIP-16 | e/f에 장착, 두 핀 열 간격 7.62 mm, 8개 행 사용 |
| 칩 방향 | 보드 기준 0° / 180° |
| 보드 방향 | 0° / 90° 비교; 직접 편집은 180° / 270°도 허용 |
| 좌표 | 회전 후 보드 외곽의 왼쪽 위가 X/Y, 단위 mm |

전원 레일의 중간 단절은 표시 설정이다. 레일 배선을 완료한 것으로 취급하지 않는다.
칩 사이 빈 행은 간격 예약이며 디커플링 커패시터·스위치·헤더의 외형 모델은 없다.
보드 프로파일과 칩 핀 매핑은 별도 정의(`breadboard.py`, `package_pins.py`)다.

## 탐색과 비용

배열 계열과 보드 방향을 열거하고, 단계별/니블별 초기 배치에서 제한된 무작위
이동·교환·회전·같은 보드의 칩 묶음 이동을 수행한다. 겹침·행 범위·그룹·고정
조건을 위반하는 후보는 버린다. 비용이 낮은 이동과 온도에 따른 일부 불리한
이동을 받아들이며 방문한 유효 후보를 보존한다.

시도 수는 모든 배열에 나누어 배정한다(40–1600회). 초기 배치 평가가 추가되므로
시도 수와 평가 수는 다르다. 샘플링 반복에는 12초 상한도 있다. 시드와 설정이
같으면 시간 상한에 걸리지 않는 범위에서 재현된다. 배치 실패는 해당 초기화와
유한 탐색에서 찾지 못했다는 뜻이며 물리적으로 불가능하다는 증명이 아니다.

신호·제어 넷 중 칩 핀이 2개 이상인 넷에 대해, 핀 좌표 사이 맨해튼 거리로
최소 신장 트리(MST)를 만든다. 이 **예상 길이**가 탐색 비용의 기준이다.

`가독성 벌점 = 3 × 153 비트 순서 역전 수 + 2 × 보드별 추가 칩 종류 수 + 뒤집은 칩 수`

| 우선순위 | 점수: 예상 mm + 가독성 벌점 × 계수 + 보드 간 점퍼 × 계수 |
|---|---|
| 배선 길이 | 예상 mm + 벌점 × 2 |
| 절충 | 예상 mm + 벌점 × 35 + 보드 간 × 12 |
| 가독성 | 예상 mm + 벌점 × 180 + 보드 간 × 35 |

목록에는 배열 계열별 최저 점수 후보, 짧은 후보, 정돈된 후보 등을 최대 8개 표시한다.
모든 가능한 배치에 대한 최적해가 아니라 **평가한 후보 중의 비교 결과**다.

## 경로와 구멍 주소

선정한 후보에는 별도로 신호 점퍼 경로를 만든다. 칩 핀이 꽂힌 e/f 구멍은
점퍼에 재사용하지 않는다. 같은 접점 묶음의 d/c/b/a 또는 g/h/i/j에서 빈 구멍을
할당하고, 칩 몸체를 피해 직교 경로를 고른다. 선을 따라 표시되는 `B2:g20`은
2번 보드의 g열 20행이다. 파란 점선은 점퍼가 아니라 빵판 내부 접점 연결이다.

경로는 직접 L자와 칩 외곽 주변의 우회 경로 후보 중에서 선택한다. 일반적인
완전 자동 배선 알고리즘이 아니므로 경로를 못 찾으면 미해결 진단을 남긴다.
**경로 후보 합**은 성공한 경로만 합산한다. 미해결 진단이 있는 결과는 배선 완료가 아니다.
길이는 평면 길이이고 점퍼 높이·끝단 삽입 깊이·여유 길이는 제외한다.

교차 지점 수는 다른 넷의 직교 선분 교차를 센다. 겹쳐 달리는 구간·선 두께·실제
높이 충돌은 계산하지 않는다. 따라서 숫자만으로 실물 조립 성공을 판정하지 않는다.

**전원/GND/Enable 타이, 전원 레일 간 점퍼, 외부 입력·출력, 디커플링 실장과
타이밍은 이 탐색의 비용·경로에서 제외한다.** 외부 구동이 필요한 넷도 칩 사이
분기 연결은 평가할 수 있지만, 외부 구동원에서 들어오는 선의 길이는 포함하지 않는다.
현재 모델은 칩 간 신호 점퍼 90개를 대상으로 한다.

## 검증과 API

```powershell
uv run --python .venv\Scripts\python.exe -m simulators.cyclesim test
uv run --python .venv\Scripts\python.exe -m simulators.cyclesim.verify_placement
```

단위 테스트는 DIP 방향/구멍/접점, 보드 변환, 충돌 거부, 고정 조건, 재현성,
접점 중복 사용 방지, 경로 몸체 회피와 길이를 검증한다. HTTP 테스트는 탐색이
ALU 상태를 바꾸지 않는지 확인한다. Playwright는 탐색·고정·재탐색·수동 편집·
오류·저장/불러오기·CSV·연결 실패·오래된 응답·화면 크기를 검증한다.
산출물은 `simulators\cyclesim\build\viewer-evidence\placement-*`에 저장된다.

- `GET /api/placement/profile`: 모델 버전·보드 프로파일·제외 범위.
- `POST /api/placement/search`: `{request_id, settings}` → 유한 탐색 후보·통계.
- `POST /api/placement/evaluate`: `{request_id, settings, boards, placements}` → 재검증한 후보.

같은 서버에서 배치 계산은 한 번에 하나만 실행한다. 중복 요청은 409를 반환한다.
별도 잠금을 사용하므로 배치 탐색이 시뮬레이터 상태 잠금을 점유하지 않는다.
